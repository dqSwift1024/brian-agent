# 监控页面产品需求文档 (PRD)

## 1. 文档概述

| 项目 | 内容 |
| :--- | :--- |
| **页面名称** | 系统监控仪表盘 (System Monitor Dashboard) |
| **所属模块** | 系统管理 / 运维监控 |
| **目标用户** | 系统管理员、运维人员、开发者 |
| **核心价值** | 实时掌握系统组件健康、宿主机资源、Token 消耗及运行日志，快速定位与排查异常 |

## 2. 页面布局结构

页面采用垂直流式布局，从上至下依次为：
1.  **全局告警横幅**（条件触发）
2.  **页面标题与刷新控制栏**
3.  **组件健康状态区**
4.  **宿主机资源使用区**
5.  **Token 使用统计区**
6.  **日志可视化区**

## 3. 功能详细设计

### 3.1 全局告警横幅

-   **触发条件**：
    -   任一组件状态为 `ERROR`；
    -   任一资源（CPU/内存/磁盘）使用率 > 90%；
    -   近 1 分钟 ERROR 级别日志数量超过阈值（默认 50 条/分钟）。
-   **展示位置**：页面最顶部，吸顶显示。
-   **展示内容**：告警图标 + 告警对象名称 + 告警级别 + 告警时间 + 详情摘要。
-   **交互逻辑**：
    -   提供关闭按钮，点击后当前会话内隐藏该条告警。
    -   下次刷新时若异常仍存在，则重新显示。
    -   多条告警时优先显示最高级别，或轮播展示。
    -   点击日志类告警横幅，自动滚动至日志区并预填对应筛选条件。

### 3.2 页面标题与刷新控制栏

-   **页面标题**：固定显示"系统监控"。
-   **最后更新时间**：格式 `HH:mm:ss`，每次数据刷新成功后更新。
-   **自动刷新开关**：
    -   默认开启，间隔 30 秒。
    -   页面不可见时暂停，恢复可见时立即刷新一次并重启定时器。
-   **手动刷新按钮**：点击触发全量刷新，刷新期间按钮置灰并显示加载态。

### 3.3 组件健康状态区

#### 3.3.1 布局规范
-   卡片网格布局：宽屏 6 列（全部组件一行）/ 中屏 3 列 / 窄屏 2 列。
-   卡片为纵向布局：顶部组件名 + 状态点，中部 `details` 键值对（数据量统计），底部响应时间/实例数。

#### 3.3.2 组件卡片信息定义

| 字段 | 说明 | 数据来源 |
| :--- | :--- | :--- |
| 组件名称 | LLM Provider / MCP / RelationDB / GraphDB / VectorDB / MQ | 配置枚举 |
| 状态指示灯 | 🟢 healthy / 🟡 degraded / 🔴 unhealthy | `/api/monitor/health-all` |
| 状态文字 | 与指示灯对应的中文状态（健康/降级/异常） | `/api/monitor/health-all` |
| 响应时间 | 组件 `message` 中的探测耗时/实例数/消息数 | `/api/monitor/health-all` |
| 数据量统计 | 组件 `details` 键值对（数据表/记录总数、节点/边、向量/维度、提供商/模型、实例、队列统计） | `/api/monitor/health-all` |

> 顶层 `status` 为 `healthy`（全部健康）/ `degraded`（有降级）/ `unhealthy`（有异常），`uptime` 为运行秒数。

#### 3.3.3 监控组件及指标矩阵

| 组件 | 核心监控指标 | 调用接口 |
| :--- | :--- | :--- |
| LLM Provider | 连接状态、响应时间、Provider 列表 | `visualizedLLM` |
| MCP | 进程状态、响应时间、已安装实例数 | `visualizedMCP` |
| RelationDB | 连接状态、查询响应时间、慢查询数 | `visualizedDB` |
| GraphDB | 连接状态、节点数量、边数量 | `visualizedGraph` |
| VectorDB | 连接状态、向量数量、维度信息 | `visualizedVector` |
| MQ | 队列状态、积压消息数、消费者数 | `visualizedMQ` |

### 3.4 宿主机资源使用区

#### 3.4.1 布局规范
-   三列等宽卡片并排：CPU / 内存 / 磁盘。
-   每张卡片左侧环形进度图，右侧数值详情。

#### 3.4.2 各卡片字段定义

| 资源 | 环形图 | 主数值 | 辅助信息 |
| :--- | :--- | :--- | :--- |
| CPU | 使用率百分比 | `XX%` | 核心数、1/5/15min 负载均值 |
| 内存 | 使用率百分比 | `XX%` | 已用 / 总量 |
| 磁盘 | 使用率百分比 | `XX%` | 已用 / 总量、数据目录占用 |

#### 3.4.3 颜色阈值规范

| 使用率范围 | 颜色 | 色值参考 |
| :--- | :--- | :--- |
| < 70% | 绿色 | `#52C41A` |
| 70% ~ 90% | 黄色 | `#FAAD14` |
| \> 90% | 红色 | `#FF4D4F` |

### 3.5 Token 使用统计区

#### 3.5.1 统计卡片（四列并排）

| 卡片 | 指标 | 格式化规则 |
| :--- | :--- | :--- |
| 今日 Token 用量 | 当日累计 Token 消耗 | ≥1M → x.xM，≥1K → x.xK |
| 本月 Token 用量 | 当月累计 Token 消耗 | 同上 |
| 今日请求次数 | 当日 LLM API 调用次数 | 同上 |
| 平均响应时间 | LLM 平均响应耗时 | ms 单位，>1000ms 自动转 s |

#### 3.5.2 Token 使用趋势图（GitHub 贡献图风格日历热力图）
-   以日历热力图展示每日 Token 消耗强度（参考 GitHub 提交贡献图）。
-   布局：周为列、周一至周日为 7 行，左侧星期标签（一/三/五/日）。
-   格子固定 10px 正方形，颜色按当日 Token 相对最大值分 4 档着色（0 为灰色空块，其余按 `brian-blue` 逐级加深），未来日期透明，hover 显示「日期: N tokens」。
-   日期范围自适应：根据展示框宽度与格子尺寸（10px + 3px 间距）动态计算周数（26~156 周），铺满容器、避免留白。
-   底部色阶图例「少 → 多」。

#### 3.5.3 模型 Token 分布图（按类型 tab + 横向条形图）
-   按模型类型分组，顶部 tab 切换：文本生成（text）/ 多模态（vision）/ 向量化（embedding）/ 已删除（deleted），仅展示有数据的类型。
-   当前 tab 内按模型展示横向条形图 + 占比百分比 + 合计 Token，按用量降序排列。
-   数据来自 `llm_usage` 聚合，模型无对应记录时显示「已删除模型」。

### 3.6 日志可视化区

#### 3.6.1 布局
-   上方：日志筛选控制栏（可换行，多组搜索条件）。
-   中部：批量操作栏（已选数量、批量复制、全选）+ 日志列表。
-   日志列表固定高度可滚动，等宽字体展示。

#### 3.6.2 日志筛选控制栏

| 筛选项 | 类型 | 选项/说明 | 默认值 |
| :--- | :--- | :--- | :--- |
| 内容搜索 | 文本输入框 | 关键词模糊匹配 message（SQL LIKE） | 空 |
| traceId | 文本输入框 | 按请求追踪 ID 搜索 | 空 |
| 模块 | 文本输入框 | 按来源模块（source）搜索 | 空 |
| 消息来源 | 单选下拉 | AOP / SYSTEM / MANUAL | 空 |
| 日志级别 | 单选下拉 | 全部 / DEBUG / INFO / WARN / ERROR | 全部 |
| 时间范围 | datetime-local 起止 | 起始/结束时间 | 空 |

#### 3.6.3 日志列表

-   **渲染**：表格形式（带表头：时间 / 级别 / 来源 / TraceId / 消息 / 操作），等宽字体，12px，固定高度可滚动，表头粘性。
-   **级别颜色**：DEBUG 灰 / INFO 蓝 / WARN 橙 / ERROR 红。
-   **每条操作**：
    -   复选框：勾选后支持批量复制/批量删除。
    -   复制按钮：复制该条完整内容（含时间/级别/模块/traceId/caller/消息），复制成功图标短暂切换为 ✓。
    -   删除按钮：删除该条日志（`DELETE /api/monitor/logs`）。
-   **批量操作**：全选/取消全选、批量复制（复制选中日志，换行拼接）、批量删除（删除选中日志）。
-   **一键清空**：清空全部日志按钮（`DELETE /api/monitor/logs/all`，二次确认）。

#### 3.6.4 日志级别分布迷你图
-   水平堆叠条形图或环形图，展示当前时间范围内各级别占比。
-   刷新频率：节流 5 秒一次。
-   点击某级别色块联动勾选/取消对应筛选。

## 4. 接口依赖清单

| 接口 | 方法 | 用途 | 刷新频率 |
| :--- | :--- | :--- | :--- |
| `/api/monitor/health-all` | GET | 聚合获取所有组件健康状态 | 30s |
| `/api/system/resources` | GET | 获取 CPU/内存/磁盘使用率 | 30s |
| `/api/analytics/token-stats` | GET | Token 统计卡片数据 | 30s |
| `/api/analytics/token-trend` | GET | Token 趋势图数据（参数: range） | 切换时 / 5min |
| `/api/analytics/model-distribution` | GET | 模型 Token 分布数据 | 切换时 / 5min |
| `/api/monitor/logs/stream` | WebSocket/SSE | 实时日志推送 | 持久连接 |
| `/api/monitor/logs/query` | GET | 历史日志查询（level, source, keyword, timeRange, limit） | 筛选变更 / 初始加载 |
| `/api/monitor/logs/sources` | GET | 日志来源模块去重列表（筛选下拉） | 初始加载 |
| `/api/monitor/logs` | DELETE | 删除指定日志（body: `ids[]`） | 删除/批量删除 |
| `/api/monitor/logs/all` | DELETE | 一键清空全部日志 | 清空 |
| `/api/monitor/logs/stats` | GET | 日志级别分布统计（参数: timeRange） | 5s / 筛选变更 |

## 5. 异常处理与容错

| 场景 | 处理策略 |
| :--- | :--- |
| 单组件接口超时/报错 | 对应卡片显示灰色 `UNKNOWN`，不影响其他卡片 |
| 资源接口失败 | 资源区显示错误提示，保留上次缓存并标注"数据可能过期" |
| Token 接口失败 | 统计卡片显示 `--`，图表区显示空状态 |
| 连续刷新失败 | 自动刷新指数退避：30s → 60s → 120s，成功后重置 |
| WebSocket 断连 | 日志面板顶部黄色提示"连接已断开，正在重连..."，指数退避重连 |
| WS 重连成功 | 拉取断连期间历史日志填补空缺，Toast 提示"连接已恢复" |
| 日志查询超时 | 日志面板显示空状态 + 重试按钮 |
| 日志量过大卡顿 | 自动降级：关闭语法高亮和关键词高亮，仅纯文本渲染 |
| 浏览器内存压力 | 日志缓存从 5000 条降至 1000 条，控制台输出警告 |
| 网络恢复 | 立即触发一次完整刷新 |

## 6. 验收标准

1.  页面加载后 3 秒内完成首屏数据渲染。
2.  组件状态灯颜色与接口返回状态严格一致。
3.  资源使用率颜色在 70%/90% 阈值边界正确切换。
4.  自动刷新 30 秒执行一次，页面隐藏时暂停，恢复后立即刷新。
5.  告警横幅在异常出现时显示，关闭后刷新仍异常时重新出现；日志告警点击可跳转并预填筛选。
6.  Token 趋势图切换时间范围后 1 秒内完成重绘。
7.  所有数值格式化符合规范（千分位缩写、响应时间单位转换）。
8.  页面进入后 2 秒内建立 WebSocket 连接并开始接收实时日志。
9.  日志流在每秒 100 条写入下保持 60fps 流畅滚动。
10. 切换日志筛选条件后 500ms 内完成历史加载并重置日志流。
11. 鼠标悬停日志面板时实时追加暂停，移出后 300ms 内恢复。
12. WebSocket 断连后 30 秒内自动重连成功，断连期间日志无丢失。
13. 日志面板高度拖拽顺滑，最小/最大高度限制生效。
14. 点击日志行复制功能在 Chrome / Firefox / Safari 均正常。
15. 页面在 1400px / 1024px / 768px / 375px 四个断点下布局正常无溢出。
