# 配置页面产品需求文档 (PRD)

## 1. 文档概述

### 1.1 产品背景

Brian-Agent 是一个多层 DDD 架构的 Agent 系统，具备 LLM 调用、记忆管理、多 Agent 协作、任务编排、自学习进化等能力。当前配置页面仅零散覆盖了 LLM Provider/Model、Soul、Skill、MCP 等少数模块的实体 CRUD，大量核心运行参数散落在各层模块的内部配置表中，无法被统一管理，远未达到"系统配置中心"的要求。

### 1.2 设计原则

- **按功能域聚合**：配置项按 Agent 系统的功能域（LLM、Agent、记忆、工具、编排等）组织，而非机械照搬代码分层。
- **配置项跟随实体**：归属某个实体的配置（如 Provider 的配额、Agent 的优化规则）应放在该实体的管理界面中，不作为独立配置项散落。
- **实体管理与参数配置并存**：有的配置是"创建/修改一个实体"（如新增一个 LLM Provider），有的是"调整一个运行参数"（如修改 context 构建的 timeline 数量），两者交互模式不同但同属一个功能域。

### 1.3 配置组织总览

```
Agent 系统配置中心
├── 1. LLM 配置            ← 提供商、模型、配额、匹配策略
├── 2. Agent 配置          ← Agent 库、策略、构建、执行、上下文、进化
├── 3. 记忆与信息配置      ← 标签、摘要、向量化、上下文构建、老化清理
├── 4. 工具与技能配置      ← Skill、MCP、工具匹配与优化
├── 5. 角色与提示词配置    ← Soul、Prompt Template
├── 6. 编排配置            ← 入口、策略、执行、可视化
├── 7. 基础设施配置        ← 日志、消息队列、存储后端
└── 8. 应用配置            ← 对话、自学习、用户画像、可视化应用
```

## 2. LLM 配置

LLM 是 Agent 系统的核心能力。配置包括：管理可用的 LLM 提供商和模型、设置调用配额、控制模型匹配策略。

### 2.1 实体管理

#### 2.1.1 LLM Provider（提供商）

Provider 代表一个 LLM 服务端点。用户可按需新增，删除，修改，搜索，启用/禁用模型提供商。

**字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `llm_provider_id` | UUID | 是 | 提供商ID |
| `llm_provider_title` | String | 是 | 提供商名称（如 OpenAI、DeepSeek） |
| `llm_provider_url` | URL | 是 | API 端点地址 |
| `llm_provider_brief` | Text | 否 | 描述说明 |
| `get_models_path` | Text | 否 | 获取模型列表接口 |
| `api_key` | Secret | 否 | API 密钥（脱敏存储和显示） |
| `enable` | Boolean | — | 启用/停用 |

**每 Provider 的配额设置**：

| 配额项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| 每日 Token 限额 | INT | 0 | 0 = 不限制 |
| 每周 Token 限额 | INT | 0 | 0 = 不限制 |
| 每月 Token 限额 | INT | 0 | 0 = 不限制 |
| 每日调用次数限额 | INT | 0 | 0 = 不限制 |
| 每周调用次数限额 | INT | 0 | 0 = 不限制 |
| 每月调用次数限额 | INT | 0 | 0 = 不限制 |

> **设计要点**：配额是 Provider 的属性，在 Provider 详情中配置，而非作为独立配置项平铺在列表中。

**操作**：新建 Provider、编辑、删除、启停、连接测试、**获取模型列表**。

> **获取模型列表 & 添加至可用模型**：Provider 详情内可「获取模型列表」拉取该提供商全部模型（写入 `llm_cache`），勾选模型后点击「添加至可用模型」批量加入系统可用模型。批量添加时需选择**用途类型**（`llm_type`：文本生成 text / 多模态 vision / 向量化 embedding），后端 `POST /api/config/provider/{id}/models/add` 携带 `llm_type` 写入 `llm_available`，避免 embedding 模型被误配为文本生成。

#### 2.1.2 LLM Model（模型）

每个 Provider 下可配置多个 Model。系统预置各 Provider 的常见模型（如 gpt-4o、claude-3-5-sonnet），用户可自定义添加。

**字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `llm_provider_id` | Ref | 是 | 所属 Provider |
| `llm_title` | String | 是 | 模型名称（如 gpt-4o） |
| `llm_brief` | Text | 否 | 模型简介（参与 LLMCore 动态模型选择排名） |
| `llm_type` | Enum | 否 | 用途类型：text（文本生成）/ vision（多模态）/ embedding（向量化） |
| `max_tokens` | Int | 否 | 最大 Token 数（不超过提供商上限） |
| `model_usage` | Text | 否 | 模型用途描述（参与 LLMCore 动态模型选择排名） |
| `enable` | Boolean | — | 启用/停用 |

**操作**：新建 Model、编辑、删除、启停、设为系统默认、连接测试、**模型测试**。

> **启用/停用**：模型卡片头部以状态圆点（绿=启用、灰=停用）展示启用状态，卡片底部提供 **启用/禁用 toggle 开关**（含默认模型）。切换调用 `PUT /api/config/model/{id}`，请求体携带布尔字段 `enable`（`true`/`false`），后端据此写入 `llm_available.enable`（DB 内为 1/0）。**启用状态统一用布尔 `enable` 表示，不再使用 `'active'/'inactive'` 字符串**。

> **模型测试**：编辑模型弹窗内提供文本输入框与「发送」按钮，按模型的用途类型调用不同接口——**文本生成/多模态模型**调用对话补全接口（`/api/config/model/{id}/chat`）执行推理；**向量化模型**调用向量化接口（`/api/config/model/{id}/embed`）生成向量，返回向量维度、Token 数与耗时。返回结果在输出框内展示，若为 JSON 内容则自动缩进格式化，同时展示输入/输出 Token 数与耗时。
>
> 模型测试**仅调用当前编辑的模型**（后端以 `no_fallback=true` 关闭模型降级回退），失败时直接展示该模型自身的调用错误（如 `LLM 调用失败: HTTP 404 ...`），不显示"所有可用模型均调用失败"等降级语义。

### 2.2 运行参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 全局每日 Token 限额 | INT | 0 | 所有 Provider 合计的每日 Token 上限（0=不限，与 Provider 级限额取较严者） |
| 全局每周 Token 限额 | INT | 0 | 同上 |
| 全局每月 Token 限额 | INT | 0 | 同上 |
| 全局每日调用次数限额 | INT | 0 | 同上 |
| 全局每周调用次数限额 | INT | 0 | 同上 |
| 全局每月调用次数限额 | INT | 0 | 同上 |
| 模型重新匹配概率 | INT | 75 | 0-100，值越大系统越倾向于重新评估当前任务应使用哪个模型 |
| 匹配排名 Prompt 模板 | Ref | — | 用于 LLM 匹配排名的 Prompt 模板 |

## 3. Agent 配置

Agent 层管理 Agent 实例的创建、策略选择、上下文构建、执行控制与持续进化。

### 3.1 Agent 实例库

Agent 实例是系统中执行任务的工作单元。每个 Agent 绑定了策略、LLM、Soul，通过任务签名进行匹配复用。

**Agent 实体字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `agent_name` | String | 是 | Agent 名称 |
| `agent_type` | Enum | 是 | 类型：WORKER（工作Agent）/ PLANNER（规划Agent）/ WRITER（写作Agent）/ EVOLUTOR（进化Agent） |
| `strategy_id` | Ref | 是 | 绑定的执行策略 |
| `llm_id` | Ref | 是 | 绑定的 LLM 模型 |
| `soul_id` | Ref | 否 | 绑定的人格 Soul |
| `task_signature` | Text | 是 | 任务签名（用于匹配相似任务复用 Agent） |
| `enable` | Boolean | — | 启用/停用 |
| `eval_score` | Float | 只读 | 评估分数（系统自动更新） |
| `usage_count` | Int | 只读 | 使用次数（系统自动更新） |

**匹配参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 匹配相似度阈值 | DOUBLE | 0.7 | 任务签名相似度超过此值的 Agent 被匹配 |
| 匹配 Prompt 模板 | Ref | — | Agent 匹配排名的 Prompt 模板 |
| 最大 Agent 数量 | INT | 100 | 系统中 Agent 实例上限 |

**优化与淘汰规则**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 观察天数 | INT | 30 | 统计窗口 |
| 最小使用次数 | INT | 5 | 窗口内使用次数低于此值的 Agent 可能被淘汰 |
| 最小评估分数 | DOUBLE | 0.5 | 评估分数低于此值的 Agent 可能被淘汰 |

**界面展示**：
- Agent 以**卡片网格**（`grid-cols-2 sm:grid-cols-3 xl:grid-cols-6`）展示，卡片为正方形（`aspect-square`，宽高相同）；
- 卡片头部展示图标、名称、类型与启用状态；下方为任务描述（两行截断）；
- 绑定的组件参数（策略 / 模型 / Soul / 评分 / 使用）**分行展示**，参数名用灰色背景框、参数值用蓝色背景框区分，长值自动截断；
- 卡片底部为**启用/禁用 toggle 开关**与**删除**按钮；
- **点击卡片（空白区域）打开编辑弹窗**进行参数修改，卡片上不再设「编辑」按钮。

**操作**：删除、启用/禁用（卡片 toggle 开关）。
- **删除**：调用 `DELETE /api/agent/{id}` 删除 Agent 并级联清理其使用记录与绑定关系（agent_usage / agent_llm / agent_skill / agent_soul / agent_mcp）；
- **启用/禁用**：调用 `POST /api/agent/{id}/toggle` 翻转 enable 状态；禁用的 Agent 不会被匹配复用（matchAgent 仅匹配 enable=true），执行时也会被拒绝（execAgent 校验 enable）。

### 3.2 执行策略

策略定义了 Agent 执行任务的方式。系统内置 3 个策略：

| 策略名称 | 适用复杂度 | 最大迭代 | 适用场景 |
|----------|-----------|----------|----------|
| CoT（Chain-of-Thought） | 0–40 | 1 | 简单任务，单步推理直接回答 |
| ReAct（Reasoning+Acting） | 30–70 | 10 | 中等任务，思考→行动→观察循环 |
| Plan-and-Solve | 60–100 | 20 | 复杂任务，先制定计划再逐步执行 |

**策略实体字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `strategy_label` | String | 策略名称 |
| `suitable_complexity_min` | Int | 适用复杂度下限 0-100 |
| `suitable_complexity_max` | Int | 适用复杂度上限 0-100 |
| `suitable_domains` | JSON | 适用领域列表 |
| `execution_rule` | JSON | 执行规则（最大迭代次数等） |
| `enable` | Boolean | 启用/停用 |

**操作**：新建策略、编辑、删除（内置 3 个策略不可删除）、启停。

**界面展示**：

- 策略以**卡片网格**（`grid-cols-2 sm:grid-cols-3 xl:grid-cols-6`）展示，卡片为竖条型（`aspect-[3/2]`），显示策略名称、适用复杂度区间、适用领域，执行流摘要固定于卡片底部；
- 卡片右上角为**启用/禁用 toggle 开关**，点击直接切换（调用 `POST /api/agent/strategy/{strategy_id}/toggle`）；
- **点击卡片弹出详情弹窗**，展示策略的具体工作方式：
  - 基本信息（策略名、复杂度区间、适用领域、启停状态）；
  - 元信息（version、最大迭代次数）；
  - 执行流程可视化——steps 结构逐步展示「下一步 / 条件分支（condition_field 的 true/false 走向）/ 出错兜底」，phases 结构分阶段展示（含循环变量）；
  - 格式化（缩进）展示的 execution_rule JSON。

**策略选择参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 默认策略 ID | Ref | — | 无匹配策略时的兜底策略 |
| 策略匹配 Prompt 模板 | Ref | — | 用于策略选择的 Prompt 模板 |

### 3.3 Agent 构建

Agent 构建器负责根据任务自动分析并组装 Agent。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 任务分析 Prompt 模板 | Ref | — | 分析任务特征所用的 Prompt 模板 |
| 自动优化构建 | BOOLEAN | true | 是否在使用中自动优化 Agent 组装（实际优化由 EvolutorAgent 评估后触发） |

### 3.4 Agent 库（复用参数）

Agent 库负责任务与历史 Agent 的匹配复用（`AgentLibraryService.matchAgent`），"重新评估概率"等参数归属此处。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| Agent 重新评估概率 | INT | 75 | 0-100；1-该值 为第 1 层算法匹配成功后的直接复用概率，值越大越倾向于重新评估 |
| Agent 复用相似度阈值 | DOUBLE | 0.7 | 第 1 层算法匹配与第 2 层 LLM 打分阈值（0.0-1.0） |
| Agent 匹配 Prompt | Ref | — | 用于 Agent 匹配排名的 Prompt 模板 |
| 最大 Agent 保留数量 | INT | 100 | 超过此数量后触发老化淘汰 |

> 注：该参数原误挂在 `agent_builder.regen_rate`（构建参数页），但 AgentBuilder 模块无对应列且业务不读取，已移除；正确的归属为 `agent_library.regen_rate`。

### 3.5 Agent 执行

控制 Agent 运行时的行为参数。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|

| 反思阶段 Prompt 模板 | Ref | — | Reflect 阶段 Prompt |

| 默认最大迭代次数 | INT | 3 | 单次 Agent 执行的最大思考-行动循环数 |
| 异步 Worker 轮询间隔 | INT | 1000 | 毫秒 |

## 4. 记忆与信息配置

Agent 的记忆系统负责存储、索引、检索对话信息，通过标签、摘要、向量化、关键词等多维度组织上下文。

### 4.1 信息存储

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 信息保留最大天数 | INT | 30 | 超过此天数的信息将被自动清理 |

### 4.2 标签生成

自动为信息生成标签，用于分类与关联检索。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 启用标签生成 | BOOLEAN | false | 是否自动生成标签 |
| 标签生成 LLM | Ref | — | 执行标签生成所用的 LLM 模型 |
| 标签生成 Prompt 模板 | Ref | — | Prompt 模板 |
| 标签 Top-K 数量 | INT | 5 | 每条信息生成几个标签 |

### 4.3 摘要生成

自动为信息生成摘要（系统响应摘要由内置 SummaryAgent 生成）。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 启用摘要生成 | BOOLEAN | false | 是否自动生成摘要 |
| 摘要生成 LLM | Ref | — | LLM 模型 |
| 摘要生成 Prompt 模板 | Ref | — | Prompt 模板 |
| 摘要生成阈值 | INT | 100 | 内容不超过该字符数时直接以原文作为摘要，超过则调用 SummaryAgent 生成 |
| 摘要生成信息类型 | STRING（列表） | RESPONSE | 需要生成摘要的信息类型白名单（逗号分隔） |

> **摘要生成信息类型交互**：该参数点击后弹出信息类型选择弹窗，可增删信息类型（同一类型不可重复），保存后以逗号拼接写入 `info_core.summary_config.info_types`。

### 4.4 向量化

将信息向量化以支持语义相似度检索。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 启用向量化 | BOOLEAN | false | 是否自动执行向量化 |
| 向量化 LLM | Ref | — | Embedding 模型 |
| 向量维度 | INT | 1536 | 向量维度数（须与向量数据库表维度一致，默认 1536） |

### 4.5 Agent 上下文构建

当 Agent 执行任务时，从记忆系统中检索相关信息构建上下文，支持「默认构建」（多维度收集去重）与「自定义构建」（指定消息ID + 钉住消息）。

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 时间线基础数量 | INT | 500 | 从会话内时间线中取最近 N 条信息 |
| 标签关联基础数量 | INT | 200 | 从全系统标签关联图中取 N 条相关信息 |
| 相似度基础数量 | INT | 150 | 从全系统向量相似度检索中取 N 条 |
| 关键词基础数量 | INT | 100 | 从全系统关键词检索中取 N 条 |
| 随机采样基础数量 | INT | 50 | 从全系统随机采样 N 条（增加多样性） |
| 标签关联消息最大百分比 | INT | 20 | 标签关联消息采集数量相对于上下文总数的上限百分比（1-100%） |
| 相似度消息最大百分比 | INT | 15 | 语义相似消息采集数量相对于上下文总数的上限百分比（1-100%） |
| 关键词消息最大百分比 | INT | 10 | 关键词消息采集数量相对于上下文总数的上限百分比（1-100%） |
| 随机消息最大百分比 | INT | 20 | 随机消息采集数量相对于上下文总数的上限百分比（1-100%） |
| 关键词评分阈值 | INT | 95 | 关键词 bm25 归一化评分（0-100）截断阈值，仅保留评分不低于该值的命中 |
| 上下文总数 | INT | 1000 | 单次上下文构建最多返回的总消息条数 |
| 启用上下文快照持久化 | BOOLEAN | true | 是否保存 Agent 上下文快照与条目快照到数据库 |
| 维度优先级顺序 | STRING | PINNED,TIMELINE,TAG_RELATIVE,SIMILARITY,KEYWORD,RANDOM | 重合消息去重保留的优先级顺序（逗号分隔） |

> **维度优先级顺序交互**：该参数点击后弹出「维度优先级顺序」弹窗，展示六类采集维度（钉住消息 / 时间线消息 / 标签相关消息 / 向量相似度消息 / 关键词相关消息 / 随机关联消息）。每行支持：
> - **采集开关**：切换该维度是否参与上下文采集（关闭后该维度不再被收集）；
> - **拖动排序**：通过拖动手柄调整维度编排顺序（即 `priority_order` 的去重优先级）。
> 保存时将「已开启」的维度按当前顺序以逗号拼接写入 `context_config.priority_order`；后端以该列表为准，未列出的维度不再采集。

> **注意事项**：各维度基础数量根据优先级顺序收集，重复消息去重并保留高优先级维度的来源属性。构建出的消息对象包含消息ID、消息摘要、消息内容、消息摘要长度、消息内容长度、消息类型与消息采集方式。

## 5. 工具与技能配置

Agent 通过 Skill（自定义技能脚本）和 MCP（Model Context Protocol 外部工具）扩展能力。

### 5.1 Skill（技能）

Skill 是在沙箱中执行的 JavaScript 代码片段，Agent 可以调用 Skill 完成特定任务。

**Skill 实体字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `skill_brief` | Text | 是 | 技能描述（用于 Agent 匹配） |
| `work` | Code (JS) | 是 | 执行代码（Node.js vm 沙箱运行） |
| `scripts` | JSON | 否 | 附加脚本 |
| `references` | JSON | 否 | 参考资料 |
| `assets` | JSON | 否 | 静态资源 |
| `enable` | Boolean | — | 启用/停用 |

**操作**：新建 Skill、编辑、删除、启停、沙箱测试执行、**按名称搜索**。

**约束**：
- Skill 名称必须唯一，创建时前端检查同名 Skill 已存在则拒绝创建并提示。更新（编辑）Skill 时不做同名检查。

### 5.2 MCP（外部工具服务）

MCP 配置为顶级配置项，与 LLM 配置平级。四个内置 MCP 市场（不可新增/删除），两层管理：MCP 市场 → MCP 实例。

#### 5.2.1 MCP 市场（内置，不可新增/删除）

> **画像维度**：用户画像下的「画像维度」子页面为实体管理视图，管理画像分析维度（direction_key / direction_name / description / weight / enable / prompt_template_id / llm_temperature / llm_max_tokens / llm_id）。维度卡片采用与参数卡片一致的紧凑网格（`grid-cols-2 sm:grid-cols-3 xl:grid-cols-6`、`aspect-[3/2]`），点击卡片打开编辑弹窗，卡片底部提供启停开关与删除按钮。

### 9.4 可视化应用

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 每图最大节点数 | INT | 200 | 控制可视化图复杂度 |
| 默认消息摘要长度 | INT | 50 | 字符数 |
| 默认展开节点内容 | BOOLEAN | true | 是否默认展开 |

## 10. 配置分类与交互模式

### 10.1 实体管理 vs 参数配置

| 交互模式 | 适用场景 | 界面形态 |
|----------|----------|----------|
| **实体管理** | LLM Provider/Model、Soul、Skill、MCP Provider/Instance、Prompt Template、Agent、Strategy、Orchestration Strategy、画像维度 | 卡片网格 + 新建/编辑弹窗，支持启停、测试连接、安装/卸载等操作；实体卡片统一采用紧凑网格（`grid-cols-2 sm:grid-cols-3 xl:grid-cols-6`）+ `aspect-[3/2]` 固定比例，点击卡片即编辑，底部提供启停/测试/删除等快捷操作 |
| **参数配置** | 上述各功能域的运行参数 | 竖条卡片网格（`grid-cols-2 sm:grid-cols-3 xl:grid-cols-6`），卡片为 `aspect-[3/2]`，每张卡片直接显示控件（Switch/Select/Input）与底部「确认」按钮，点击确认保存 |

### 10.2 引用类型配置项的处理

配置项中类型为 `Ref`（引用其他实体 ID）的参数——如 "标签生成 LLM"、"匹配排名 Prompt 模板"——**前端应渲染为下拉选择器**，数据源来自对应实体列表（已启用的 LLM Model 列表、已启用的 Prompt Template 列表等），而非自由文本输入。

### 10.3 关联实体展示

部分模块的实体之间存在关联，在详情页应展示关联信息：

- LLM Provider 详情 → 列出其下所有 Model，支持直接在此新建 Model
- Agent 详情 → 展示其绑定的 Strategy、LLM、Soul 名称及状态
- Skill 详情 → 展示被哪些 Agent 引用
- MCP Provider 详情 → 列出已安装的 MCP Instance

## 13. 非功能性需求

- **性能**：全量配置加载 < 2s；单个配置保存响应 < 500ms；连接测试超时 10s。
- **安全**：API Key 类字段脱敏展示（`sk-****abcd`），点击可短暂查看；关键配置变更需确认。
- **无障碍**：WCAG AA 级别，键盘完全可操作。
- **兼容性**：Chrome/Edge/Firefox/Safari 最新两个主版本，最小宽度 375px。
- **数据一致性**：配置修改后独立路由页面（/models、/souls 等）即时同步。
