# Brian-Agent 单文件可执行打包

将整个系统（后端 5 层 + 前端 + 原生模块 + 内置 Chromium）打包为一个**单文件可执行**，支持 Windows / Linux / macOS 三平台，目标机器无需安装 Node.js。

## 1. 打包原理

采用 **Node.js 官方 SEA（Single Executable Application）** 技术，结合 esbuild 打包：

```
后端 TS ──esbuild──► bundle.cjs（内联前端静态文件 + jieba 词典）──┐
原生模块（.node × 4）────────────────── SEA asset ───────────────┤──► node --experimental-sea-config
内置 Chromium（Chrome for Testing）── append 到可执行文件末尾 ───┘    + postject ──► 单文件可执行
```

| 组件 | 集成方式 |
|------|---------|
| 后端 + 前端 | esbuild 打包为单 CJS bundle，前端 dist 内联为 base64 映射 |
| `better-sqlite3` / `isolated-vm` / `@node-rs/jieba` / `@lancedb/lancedb` | `.node` 内嵌为 SEA asset，运行时解压到临时目录 + `process.dlopen` 加载 |
| Chromium（CDT 浏览器自动化） | 追加到可执行文件末尾（footer 标记），运行时从自身提取解压 |

**关键点**：
- SEA 的 `require` 默认只加载 built-in，打包入口通过 `createRequire` 恢复文件系统加载；
- `postject` 有 256MB WASM 内存限制，故 Chromium（>100MB）不放进 SEA blob，而是 append 到文件末尾（ELF/PE 加载器会忽略尾部额外数据）。

## 2. 打包相关文件

| 文件 | 作用 |
|------|------|
| `packaging/build.mjs` | 构建脚本（esbuild 打包 + SEA 生成 + postject 注入 + Chromium 追加） |
| `packaging/entry.ts` | SEA 入口（安装原生模块拦截 → 配置数据目录 → 加载后端） |
| `packaging/setup-native.ts` | 原生模块解压 + `Module._resolveFilename` 拦截 |
| `packaging/setup-chromium.ts` | 内置 Chromium 提取 + 解压 + 设置 `BRIAN_CHROME_PATH` |

## 3. 构建步骤

> 必须在**目标平台**上执行构建（原生 `.node` 与 node 二进制均为平台特定）。

```bash
# 0) 确保 Node 22 + 依赖就绪
nvm use 22
npm install

# 1) 构建前端（首次或前端改动后）
npm run build:frontend

# 2) 打包单文件可执行（自动下载对应平台的 Chrome for Testing）
node packaging/build.mjs

# 跳过内置 Chromium（体积更小，CDT 回退到系统 Chrome）
node packaging/build.mjs --skip-chromium
```

产物在 `dist-sea/` 下：
- Linux：`brian-linux-x64`
- Windows：`brian.exe`
- macOS：`brian-darwin-x64` / `brian-darwin-arm64`

## 4. 运行时行为

启动单文件可执行后（`./brian-linux-x64`），系统自动：

| 资源 | 位置 | 说明 |
|------|------|------|
| 数据目录 | 可执行文件旁 `data/` | 可用 `BRIAN_DATA_DIR` 覆盖 |
| 原生模块 | `/tmp/brian-agent-native/{platform}-{arch}/` | 首次解压，后续缓存 |
| 内置 Chromium | `/tmp/brian-agent-chromium/{platform}-{arch}/` | 首次解压，后续缓存 |
| 后端端口 | 8000 | 可用 `BRIAN_PORT` 覆盖 |
| 前端 | 由后端 serve（`/`） | 单端口交付 |

## 5. 注意事项

- **首次启动较慢**：需解压 Chromium（~170MB），后续启动复用缓存。
- **体积**：完整版约 400MB（node 运行时 ~230MB + 后端 ~30MB + Chromium ~170MB）。
- **macOS 签名**：构建后需 `codesign --sign - <可执行文件>`（未签名仍可运行但会告警）。
- **Windows**：`postject` 需 PowerShell/命令提示符环境；macOS x64 平台 Node 官方未完全测试。
- **CDT 浏览器**：内置 Chromium 优先；若解压失败自动回退到系统 Chrome（可经 `cdt_config` 的 `chrome_path` 配置）。

## 6. 三平台构建清单

| 平台 | 构建机 | 产物 | 备注 |
|------|--------|------|------|
| Windows x64 | Windows | `brian.exe` | 可选 signtool 签名 |
| Linux x64 | Linux (glibc) | `brian-linux-x64` | - |
| macOS arm64 | Apple Silicon | `brian-darwin-arm64` | 需 codesign |
| macOS x64 | Intel Mac | `brian-darwin-x64` | 需 codesign |
